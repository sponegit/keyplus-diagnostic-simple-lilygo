> `[OTA] pending ack: … 기대=0.2.7 실행=0.2.5 → failed`

## 0.2.7 대비 변경 — 모뎀 무응답 복구 지연 단축 (실측 2분 30초 → 약 30초)

실기 로그에서 재접속이 오래 걸린 구간은 **망 등록이 아니라 복구 사다리 자체**였습니다.
등록은 한 줄 만에 `ok-home` 으로 붙는데(rssi 27), 그 앞뒤로 대기만 2분 반이었습니다.

| 시각 | 구간 | 소요 |
|---|---|---|
| 22:58:07 | 모뎀 무응답 확인 → 그냥 30초 백오프 | 42s |
| 22:58:51 | 무응답인 모뎀에 소프트 리셋(`AT+CFUN=1,1`) 시도 | 30s |
| 22:59:31 | 하드 리셋 성공·모뎀 정상 → 그런데 "60s 후" 대기 | 60s |

세 구간을 모두 없앴습니다.

- **AT 무응답이면 백오프를 건너뛰고 즉시 리셋으로 승격.** `[LTE] 모뎀 무응답` 이 뜬
  시점에 판정은 이미 끝난 겁니다. 백오프는 "등록이 안 붙는" 상황(전원 마진)을 위한
  것이지 죽은 모뎀을 살리지는 못합니다. 실패 횟수(`LTE_FAIL_BEFORE_RESET`)를 채우길
  기다리지 않습니다.
- **AT 를 못 받는 모뎀에는 소프트 리셋을 시도하지 않습니다.** `AT+CFUN=1,1` 도 AT 라
  닿을 리 없고 타임아웃 30초만 태웁니다 → 곧장 PWRKEY 전원 사이클.
- **리셋으로 되살아나면 쌓인 백오프를 버립니다.** 방금 부팅한 깨끗한 모뎀을 60초씩
  놀리던 부분입니다. 부팅 URC(`+CPIN: READY`, `+CGEV …`)가 정리될
  `LTE_POST_RESET_DELAY_MS`(5초)만 두고 바로 붙습니다.
- **MQTT 재접속 게이트도 같은 시점에 엽니다.** 안 그러면 LTE 는 5초 뒤 준비됐는데
  MQTT 백오프(최대 15초)가 뒤늦게 막습니다.

기대 타임라인: `링크 다운 → ~2s 무응답 확인 → 하드 리셋 ~10s → 5s 대기 →
등록+PDP+MQTT ~12s` ≈ **30초**.

> ⚠️ 이 변경은 **회복을 빠르게 할 뿐 끊김 자체를 막지 않습니다.** 위 로그에서는
> telemetry 발행 실패(`pub-FAIL`) 직후 모뎀이 AT 까지 통째로 죽었는데, 이건 정상적인
> 망 이탈이 아니라 **모뎀 크래시/브라운아웃**에 가깝습니다. 발행은 모뎀이 최대 출력으로
> 송신하는 구간이라 5V 공급 마진이 부족하면 여기서 무너집니다. 자주 반복되면 30초마다
> 리셋하는 단말이 되므로, `info` 의 `reset` 값과 전원 경로(차량 5V/배선)를 점검하세요.

## 0.2.6 대비 변경 (0.2.7)

- **유심 없이 부팅하면 단말이 통째로 멈추던 문제 수정.** `MODEM STRING NO FOUND!` 가
  12초마다 무한 반복되고 그 뒤가 진행되지 않았습니다. 원인은 모델명(ATI) 조회를 성공할
  때까지 무한 재시도하던 구조 — `setup()` 이 끝나지 않아 콘솔·OBD2·차키·LED 까지 죽었습니다.
- 모델명 조회 3회 실패 → 하드 리셋 1회 → 그래도 실패하면 `UNKNOWN` 으로 부팅 계속.
  `A7670G`(내장 GPS 없음)로 **확정된** 경우에만 기존처럼 정지합니다.
- AT 준비 대기 90초 상한, GNSS 활성화 재시도 3회 제한 — 모뎀이 안 떠도 부팅은 끝납니다.
- `Lte::begin()` 에 SIM 인식(`+CPIN?`) 선체크 — 유심 없음/PIN 잠김이면 90초 등록 폴링을
  생략하고 `[LTE] SIM 미인식 — 유심 삽입/접촉 확인` 으로 원인을 알립니다.
- `FW_VERSION` 을 `0.2.5` → `0.2.7` 로 바로잡음(0.2.6 에서 누락).

### 검증 범위

## 파일 구성

```
keyplus-diagnostic-0.2.8.bin       OTA로 내려보낼 이미지 (app 파티션 전용)
keyplus-diagnostic-0.2.8.bin.md5   MD5 한 줄 (배포 서버 검증용)
ota-manifest.json                  배포 메타 (버전/크기/해시/변경점) — url 채워서 사용
ota_start.json                     MQTT 명령 템플릿 — url/command_id 채워서 발행
```

> ⚠️ 이 `.bin`은 **app 이미지**입니다. USB로 처음 굽는 `0x0` 통합 이미지가 아닙니다.
> 시리얼 최초 플래싱은 `pio run -t upload`을 쓰세요.

## 배포 절차

1. `keyplus-diagnostic-0.2.8.bin`을 HTTP(S)로 접근 가능한 곳에 올린다.
2. `ota-manifest.json`의 `url`을 실제 주소로 채워 배포 기록으로 남긴다.
3. `ota_start.json`의 `command_id`(UUID)와 `url`을 채운다.
4. 대상 단말의 **`v1/{device_id}/cmd`** 토픽으로 발행한다 (QoS 1).
   예: `v1/vt-2607-0002-6wr/cmd`
5. 단말이 다운로드 → 플래시 → 재부팅한다.
6. 재부팅 후 MQTT 재접속되면 **`v1/{device_id}/cmd/ack`** 로 결과가 올라온다.

## ⚠️ 반드시 지킬 제약

### 1. 명령 JSON은 **약 1,000 바이트 미만**이어야 한다

래퍼(`TinyGsmMqttA76xx`)가 토픽과 페이로드를 **하나의 버퍼에** 나눠 담기 때문에,
토픽 길이만큼 페이로드 여유가 줄어듭니다(1024B − 토픽 24B ≈ 1,000B). 넘치면
**경고 없이 잘리고**, 잘린 JSON은 `url`이 빈 값이 되어 `[OTA] 잘못된 URL`로 실패합니다.

발행 전 확인:
```bash
python3 -c "import json;print(len(json.dumps(json.load(open('ota_start.json')),separators=(',',':'))),'bytes')"
```

### 2. `version`은 `0.2.8`과 **정확히** 일치해야 한다

재부팅 후 실행 이미지의 `FW_VERSION`과 대조해 ack를 결정합니다(`ota.cpp`).
불일치하면 실제로는 성공했어도 **`failed`로 ack**가 나갑니다.
**서빙하는 bin과 `version` 필드가 같은 릴리스인지 확인하세요** — 0.2.6 bin을
`version: 0.2.7`로 내려 ack가 failed로 나간 사례가 있습니다.

### 3. URL은 `http`로 시작해야 한다

`ota.cpp`가 `url.startsWith("http")`로 1차 검증합니다. HTTPS 권장.

### 4. 다운로드 중에는 MQTT가 끊긴다

모뎀의 SSL 컨텍스트를 HTTP(S)에 양보하려고 `Mqtt::stopService()`를 먼저 호출합니다.
그래서 ack는 즉시 나가지 않고 **재부팅 후 재접속 시점에 발행**됩니다(NVS pending).

### 5. 재부팅 후 10분 안에 MQTT에 붙어야 확정된다

새 이미지는 `PENDING_VERIFY` 상태로 부팅하고, MQTT 접속에 성공해야
`Ota::onHealthy()`가 확정(`mark_valid`)합니다.
`OTA_CONFIRM_DEADLINE_MS`(10분) 안에 못 붙으면 **자동 롤백 재부팅**됩니다.

→ 전파가 약한 곳이나 **전원이 불안정한 차량에서는 OTA를 피하세요.**

> 0.2.7/0.2.8의 부팅 견고화·복구 단축은 **OTA 확정 조건과는 무관**합니다.
> 확정 조건은 여전히 "10분 내 MQTT 접속"이라, 유심이 없거나 전파가 없으면 롤백됩니다.
> 유심 없는 상태의 검증은 **시리얼 플래싱**으로 하세요.

## 발행 예시

```bash
mosquitto_pub -h mqtt-dev.keyplus.sponeinfra.com -p 40102 \
  --cafile ca.pem \
  -u vt-2607-0002-6wr -P '<mqtt_pw>' \
  -t 'v1/vt-2607-0002-6wr/cmd' -q 1 \
  -f ota_start.json
```

### 진행 확인 (콘솔)

USB-C 또는 보조 UART(UART2, TX=GPIO13 / RX=GPIO34, 115200)에서:

```

  url=https://.../kpd-0.2.8.bin
  md5=362b3e740ddf2260b267861c3a6b7975
[OTA] 펌웨어 크기 386352 bytes — 플래시 시작
[OTA] 10% (38635/386352)
...
[OTA] 플래시 완료·검증 통과 — 재부팅 예약
```

재부팅 후:

```
============================================================
  Keyplus Diagnostic   fw 0.2.8
  reset      : SW(소프트 리셋/재부팅)
============================================================
[OTA] 새 이미지 확정(mark_valid) ... — 롤백 취소
[OTA] pending ack: cmd=... 기대=0.2.8 실행=0.2.8 → done
```

`info` 명령으로도 버전을 바로 확인할 수 있습니다.

## 배포 전 체크리스트

- [ ] 업로드한 파일의 MD5가 위 값과 일치 (`md5 -q <file>`)
- [ ] 서빙하는 bin이 **0.2.8 릴리스의 것**인지 (다른 버전 bin을 올리지 않았는지)
- [ ] URL이 단말에서 접근 가능 (사설망/방화벽 확인)
- [ ] `ota_start.json` 직렬화 길이 **< 1,000 bytes**
- [ ] `version` 필드가 `0.2.8`
- [ ] 대상 단말이 **`cmd` 구독 성공** 상태 — `status server`에서 `[ok]` 확인
- [ ] 단말 전원 안정 (브라운아웃 이력 없음 — `info`의 `reset` 확인)
- [ ] 1대 선행 배포 후 확대

> **0.2.6 / 0.2.1 은 사용하지 마세요.** 0.2.6은 `FW_VERSION` 누락으로 ack가 항상
> `failed`, 0.2.1은 모뎀 리셋 후 MQTT 영구 접속불가 결함이 있습니다.
