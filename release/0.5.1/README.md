## 무엇을 막나

v2 는 메인 + 서브 2보드 구조입니다. v2 메인 펌웨어는 **GPIO13/34 를 서브 링크로 쓰고
차키를 서브로 넘깁니다.** 이 이미지가 서버 실수로 v1 단말에 내려가면 차키와 콘솔이
죽고, 원격으로 되돌릴 수 있을지도 장담할 수 없습니다.

0.5.0 까지의 OTA 는 **버전 문자열이 같은지만** 봤습니다. 다른 세대 이미지를 걸러낼
수단이 없었습니다.

## 어떻게 막나 — 두 겹

| | 근거 | 시점 | 서버 의존 |
|---|---|---|---|
| ① 명령 라벨 | `ota_start` 의 `hw` 필드 ≠ `v1` | 다운로드 **전** | 있음 — 안 보내면 통과 |
| ② **이미지 마커** | 내려받는 바이너리 안의 `KPHW:<모델>` | 플래시 **확정 전** | **없음** |

②가 핵심입니다. 판정 근거가 서버 라벨이 아니라 **이미지 내용**이라, 서버가 `hw` 를
잘못 붙이거나 아예 안 보내도 막힙니다. 스트리밍 중에 1KB 청크를 훑으므로 추가 다운로드나
메모리 버퍼가 없고, 청크 경계에 걸친 마커도 잡습니다. 다른 모델이면 `Update.abort()` 하고
`failed` 를 냅니다 — 부트 파티션이 바뀌지 않으므로 **실행 이미지는 그대로**입니다.

로그:

```
[OTA] 하드웨어 마커: 일치
[OTA] 하드웨어 마커: 없음(구 이미지 — 통과)
[OTA] 다른 하드웨어 세대 이미지(v2) — 단말은 v1. 플래시 확정 안 함
[OTA] 하드웨어 세대 불일치: 명령 hw=v2, 단말 v1 — 다운로드 안 함
```

### ⚠️ 마커가 없는 이미지는 통과시킵니다

0.5.0 이하 v1 이미지에는 마커가 없습니다. 이걸 막으면 **v1 롤백이 불가능**해집니다.
v2 이미지는 처음부터 마커를 갖고 나가므로 이 예외로 새지 않습니다.

## 검증

| 항목 | 결과 |
|---|---|
| 호스트 단위 테스트 | 7종 × 청크 크기 6종(1·2·3·7·1024·전체) 통과 — 청크 경계 걸침, 부분 일치 후 재시작, 빈 모델, NUL 없음 포함 |
| 새 빌드 이미지 | 마커 **정확히 1개** (`KPHW:v1`) → 판정 **일치** |
| 0.5.0 이미지 | 마커 없음 → **통과** |
| 마커를 `v2` 로 바꾼 사본 | **거부** |
| 실기 OTA | **미실시** |

## 서버

필수 변경은 없습니다. 권장:

- `ota_start` payload 에 **`hw` 를 실어 보내기** — v1 단말이면 `"v1"`. ①이 다운로드 전에
  걸러 주므로 잘못된 OTA 에 2분씩 데이터를 쓰지 않습니다.
- 계약(`@keyplus-diagnostic/shared` `command.ts`)에 **선택 필드 `hw`** 추가.
- 실패 사유는 ack 에 실리지 않습니다(`failed` 만). 사유는 단말 로그의 `[OTA]` 줄로 봅니다.

## 한계

- **0.5.1 로 올리는 OTA 자체는 보호되지 않습니다.** 0.5.0 이하 단말은 가드를 모릅니다.
  가드는 0.5.1 이 설치된 뒤부터 동작합니다 — v2 펌웨어가 나오기 전에 v1 단말을 0.5.1 로
  올려 두십시오.

## 배포

```bash
./scripts/deploy-ota.sh 0.5.1 --dry-run   # 전송 명령만 확인

```
